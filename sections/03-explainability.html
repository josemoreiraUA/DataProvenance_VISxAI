The theoretical formalisms proposed in [REF1, REF2] have been implemented in provenance frameworks like Perm [REF], GProM [REF], ProvSQL [REF] and DataProv [REF], primarily targeting database systems and query processing. They follow the same underlying principles, but their notation and terminology may differ slightly. These provenance representations also provide a foundation for end-to-end explainability by enabling data contributions to be traced from their sources through processing pipelines to analytical and machine learning outcomes.

Lineage

Lineage is the most basic form of data provenance. It identifies the input tuples that contributed to a given output record, establishing a direct link between source and derived data and providing a lightweight way to trace how data flows across processing pipelines. This simple representation allows the origins of a result to be traced back to its source records and makes data dependencies easier to understand.

Lineage can be captured during query execution or derived on demand from richer, fine-grained provenance representations, such as provenance polynomials or semiring annotations. For example, in a database query joining a customer table with a transaction log, fine-grained provenance might record the exact join condition and feature scalings applied ($t_1 \cdot t_2$). ~ In contrast, lineage simplifies this result into the minimal source set—specifying simply that output record $R_1$ was derived from Customer tuple $C_{104}$ and Transaction tuple $T_{892}$.

While lineage identifies which source tuples contributed to a result, provenance polynomials provide a richer explanation of how and why those tuples contributed by capturing the structure of their derivations, including alternative and joint contributions. For aggregate queries, semimodule annotations further associate each contributing tuple with the value it contributes to the aggregate, making it possible to determine not only which tuples influenced the result, but also how their individual values contributed to the final aggregate.
