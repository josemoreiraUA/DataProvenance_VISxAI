There are several forms of data provenance that capture complementary aspects of how data is produced and consumed at different levels of granularity. This work focuses on tuple-level provenance, the most fine-grained form of provenance, which identifies the source records that contributed to each output tuple and describes how and why they contributed to its creation. Such fine-grained provenance is particularly valuable for Explainable AI, as it enables users to trace the origin of the data used to train or execute a model, thereby improving the transparency, explainability, and trustworthiness of its predictions.

A provenance semiring is an algebraic structure $( \mathbb{K}, +, \cdot \, , 0, 1)$, where $\mathbb{K}$ denotes a set of provenance tokens, $+$ is a commutative and associative operator with identity \( 0 \), and $\cdot$ is a commutative and associative operator with identity \( 1 \) distributive over $+$ [REFS]. The semiring addition operator (+) represents alternative derivations of a tuple, while the multiplication operator (·) represents joint participation of tuples in the same derivation. These algebraic annotations can be combined and propagated through the query evaluation process according to the semantics of the relational algebra Selection, Projection, Join and Union operators, while preserving the semantics of the original query. Thus, the provenance of each output tuple can be expressed as a provenance polynomial that compactly encodes all possible derivations leading to that result.

Aggregation queries require a richer provenance model because the result depends not only on which tuples contributed to the computation, but also on the values they contributed. To address this limitation, provenance semirings are extended by introducing a semimodule structure defined over a semiring and a monoid ($K \otimes M$), where $K$ is a commutative semiring and $M$ is a commutative monoid representing the aggregation domain. For instance, the SUM aggregation is defined over the commutative monoid (R,+,0), where R is the set of real numbers, + is the addition operation and 0 is its identity element. This extension preserves both the computed value and the contribution of every participating tuple, enabling understanding not only which records contributed to the derivation of a data item but also how strongly they influenced aggregated features.

Data provenance can addresses this gap by acting as an audit trail that documents the complete lifecycle of data from origin to consumption. Frameworks like the W3C PROV data model formalize these relationships by linking Entities (data artifacts), Activities (processing steps), and Agents (systems or users), while workflow provenance tools capture the exact execution environments of machine learning pipelines. Depending on the application, provenance can be tracked at varying levels of granularity—ranging from coarse-grained dataset lineage to fine-grained row- and cell-level tracking—revealing not just which features drove an AI decision, but why those features took those values in the first place.
